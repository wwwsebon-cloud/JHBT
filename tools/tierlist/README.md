# 티어 시뮬 (R2.22.2)

지후배틀 R1 (`archive/v8.1` 브랜치 `tools/tierlist/`) 방식을 R2 엔진에 맞게 옮기고 강화했다.

```
tools/tierlist/run.sh <버전> [판수=1600] [병렬=4] [부트스트랩=100]
```

로컬 서버(8766)를 켜고 → 헤드리스 크롬 일꾼 여러 개가 판을 나눠 돌리고 (`run.js` + `harness.js`) → 집계 (`agg.js`) → 반영 (`apply.py`) → 티어표 인포그래픽 (`make.py` · `shot.py`) 까지 한 번에 한다.
Firebase 등 바깥 주소는 막는다. 1,600판 · 병렬 4개는 클라우드 4코어에서 몇 분.

## 계산 (R1 과 같음)

- 판마다 무작위 10기를 5:5 로 붙인다 · Lv1 · 랭크 없음 · 이벤트 없음 · 60초가 지나면 남은 체력으로 판정 · 판마다 전투 시드 고정.
- 결과 점수 `y = 0.5 + (아군 − 적 남은 체력 비율 평균) / 2` (승패 0/1 보다 순위가 안정적).
- 팀 실력 모델 (Bradley-Terry): 지후마다 점수 s · `P(아군 승) = σ(Σ아군 s − Σ적 s)` 가 모든 판에 가장 잘 맞게 (L2 λ 0.5 · 뉴턴법). 표시 승률 = σ(s) (50% = 평균) · 오차 = 헤세 역행렬 대각.
- 티어: 비율로 자르지 않고 점수가 크게 벌어지는 곳에서 자른다 (1차원 최적 k-평균 · 한 티어 최소 2기). R1 은 6개 · R2 는 **S ~ D 5개**.

## 파일

- `run.sh` — 한 번에 돌리기 (`TIER_WORK` 작업 폴더 · 기본 `/tmp/jhbt-tier-<버전>` · `NO_APPLY=1` 이면 집계까지만).
- `run.js` — 일꾼 (`node run.js <작업폴더> <번호> <일꾼 수> <판수>`) · 판 g 는 짝 ⌊g/2⌋ · 홀수면 진영 바꿈 · 시드 1000 + ⌊g/2⌋.
- `harness.js` — 페이지에 넣는 전투 (`window.__tl.fight`) · 계산은 예전 콘솔용 `tools/tier-5v5.js` 와 같다.
- `agg.js` — 집계 (`agg.json` · `result.txt`: 순위 · 티어 (지난 티어) · 승률 ±90% · 실제 승률 · 판 수 · 피해 비중 (팀 평균 = 1) · 안정도).
- `apply.py` — 반영. `TIER_SC` 는 티어마다 점수 띠 (S 80~100 · A 65~79 · B 40~64 · C 20~39 · D 0~19) 안에 승률 순으로 고르게.
- `history/` — 버전마다 결과.
