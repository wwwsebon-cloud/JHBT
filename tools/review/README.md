# 주기적 코드 리뷰 · 리팩터링 (R2.36)

`index.html` 하나가 게임 전체라서, 동작을 바꾸지 않는 정리 (재배열 · 머리말 · 죽은 코드 삭제) 를 안전하게 하기 위한 도구와 순서.

## 순서
1. **기준선**: 고치기 전에 고정 시드 전투를 저장한다 (로컬 서버 8766).
   `cd tools/tierlist && for w in 0 1 2 3; do node run.js <폴더>/base $w 4 120 & done; wait`
2. **조사**: `python tools/review/survey.py` — 안 쓰는 함수 · 변수 · CSS 클래스 · 머리말 없는 긴 구간.
3. **정리**: index.html 은 `newline=''` 파이썬 치환으로 (줄바꿈이 섞여 있다). 블록을 옮길 때는 통째로 (최상위 `const` 는 선언보다 먼저 쓰이면 로딩 때 오류 → 5번에서 잡힌다).
   - 안 쓰는 CSS: `python tools/review/css-prune.py [--dry] <클래스 …>` (접두사는 `evf-*`).
   - 큰 구간을 만들거나 옮기면 `// ═════════ 제목 ═════════` 머리말 → `python tools/review/toc.py` (스크립트 맨 위 목차).
4. `python tools/comment-check.py` 「의심 0줄」.
5. **검증**: 같은 시드로 다시 돌려 `sort` 한 `t5_*.jsonl` 이 기준선과 `cmp` 로 같아야 한다 (전투 결과가 한 글자라도 다르면 동작이 바뀐 것) — **코인 지후가 낀 판은 빼고 비교한다** (`grep -v '"coin"'` · 공격력이 실제 시각의 10분 칸 시세라 시간이 지나면 달라진다) · 빈 브라우저 첫 로딩 (오류 없이 로비) · `?bench=50`.

## 옮기지 않는 것
- 전투 난수 `rng` 를 부르는 순서가 바뀌는 수정 (친선전 · 리플레이가 어긋난다).
- `PATCH_NOTES` · `CHARS` 의 순서 (출시 순 · 도구들이 순서를 쓴다).
